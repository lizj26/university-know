# 「XX 知道」修改指南

面向要改这个站点的人：**第一部分**讲怎么给各个学校换 / 加信息源，**第二部分**讲怎么改页面风格。

> **先记住三条**
> 1. 真正的源文件只有两个：`template.html`（页面结构、样式、交互）和 `data/<校区>.json`（内容）。
>    `index.html` 是 `refresh.py` 生成出来的**产物，不要手改**，下次生成会被覆盖。
> 2. 改完必须重新生成：`python refresh.py --build-only`（不联网，只用现有数据重排页面）。
>    `--import` 导入数据时会自动重新生成，不用再手动跑一次。
> 3. 改完双击 `index.html` 看一眼；改动大就跑一下自检脚本（见第三部分）。

---

# 第一部分：信息源

## 1.1 数据是怎么流到页面上的

```
pkuknow.cn 聚合接口 ──→ refresh.py 抓取      ─┐
                                              ├─→  data/<校区>.json  ─→  refresh.py build()  ─→  index.html
学院官网 + 官方公众号 ──→ fetch_campus.py 抓取 ─┘         ↑                                          │
                                                页面的唯一内容来源                    内嵌 <script id="notice-data">
                                                                                                │
                                                                                     浏览器按校区渲染成卡片
```

`refresh.py` 的 `build()` 会把 `data/` 下**所有** `*.json` 打包成一个 JSON 内嵌进 `index.html`，
文件名（不含 `.json`）就是校区 key。所以「增删一个校区」在数据层面就是增删一个数据文件。

两个脚本的分工：**浙大 / 上交 / 西交**走 `fetch_campus.py`（直接抓官网 + 职能部门，见 1.4），
产出 `data/<校区>.json`；`refresh.py` 负责把这些数据合并内嵌进 `index.html`（`--build-only`），
也保留了走 pkuknow.cn 上游聚合接口的能力。**「清华知道」在顶栏是外链**（直达 pkuknow.cn/thu），
本站不抓取它。

## 1.3 重建页面（`refresh.py --build-only`）

「清华知道」在顶栏是外链，本站不抓取它的内容；`refresh.py` 现在主要用来**建站**：

```bash
python refresh.py --build-only         # 不联网，用 data/*.json 重建 index.html（最常用）
python refresh.py --limit 300          # 上游模式：只抓最近 300 条（仅当某校配了上游前缀）
python refresh.py --no-details         # 上游模式：只要标题列表，不带摘要/正文
python refresh.py --campus <key>       # 上游模式：指定校区（没配前缀的会跳过并说明）
```

写盘时有几道保护，避免一次网络抖动就把好数据写坏：

- 列表页失败、实际条数比目标少 2% 以上、上游 `total_all` 异常、或比上次缩水 10% 以上 → **默认不写**，
  保留旧数据并说明原因；确实要写残缺数据加 `--allow-partial`。
- 写之前自动备份成 `data/<校区>.json.bak`，写入是原子的（先写临时文件再替换）。
- 某条详情抓取失败 → 沿用上一次抓到的详情，不会把摘要清空（会在 `fetch_warnings` 里记一笔）。

## 1.4 抓浙大 / 上交 / 西交的学院官网与官方公众号（`fetch_campus.py`）

三个新校区的内容由 `fetch_campus.py` 从**学院官网 + 官方微信公众号**抓取（清华仍走 `refresh.py`
的聚合接口）。一条命令：

```bash
python fetch_campus.py                      # 抓 zju / sjtu / xjtu 三校，写入 data/ 并重新生成页面
python fetch_campus.py --campus zju         # 只抓浙大
python fetch_campus.py --max-per-source 8   # 每个来源最多取 8 条（默认 15）
python fetch_campus.py --workers 6          # 并发抓 6 个来源（默认 4；不同主机并行、同主机仍限速）
python fetch_campus.py --retries 1          # 单页失败只重试 1 次（默认 2，网络受限时压耗时）
python fetch_campus.py --no-details         # 只抓标题/时间/链接，不抓正文（快很多）
python fetch_campus.py --no-import          # 只抓取，结果落在 _work/items-<校区>.json
python fetch_campus.py --import-only        # 不联网，把 _work/ 上次的结果写入 data/
```

清单写在 `fetch_campus.py` 顶部的 `SOURCES` 里，加一行就多一个来源：

```python
{"id": "sjtu_math", "name": "上海交大数学科学学院", "group": "official",
 "url": "https://math.sjtu.edu.cn/xxgg.htm", "kind": "list", "max": 12},
```

- `kind: "list"` —— 抓列表页里的文章链接（脚本自动识别“像文章”的链接，再进正文页取标题/时间/正文）。
- `kind: "wechat"` —— 该页面本身没有文章列表，只从里面摘 `mp.weixin.qq.com` 文章链接。
- `group` —— `official` / `wechat`，决定它归到页面上的哪个来源筛选。
- `max` —— 这个来源每轮最多取几条（`--max-per-source` 可临时覆盖）。
- 分类（`c`）不用手填：脚本按标题+正文关键词套用 `CATEGORY_RULES`，映射到站点那 13 个分类；
  想调整规则就改 `CATEGORY_RULES` 里的正则，顺序即优先级。

### 不改代码就能加来源（`_work/sources-<校区>.json`）

想让抓取器“持续可用、不用改程序”，把补充来源写成一个数据文件即可：

```json
[
  {"id": "zju_math_new", "name": "某某学院", "url": "https://xxx.zju.edu.cn/tzgg/list.htm",
   "kind": "list", "max": 8},
  {"id": "zju_lib", "enabled": false}
]
```

- 文件放在 `_work/sources-zju.json`（或 `sources-sjtu.json` / `sources-xjtu.json`），
  与 `SOURCES` 同 id 会**覆盖**内置配置，`"enabled": false` 可**临时停用**某个来源（不抓仍保留注册表记录）。
- 格式也可写成 `{"sources": [...]}`；坏条目（缺 `id`/`url`）会被跳过并提示，不会让整轮抓取失败。
- 这个文件属于 `_work/`，是**手工维护文件**，别当成生成物删掉。

另外两条“新内容不会漏”的保障：

- 每轮重爬列表页并按 `i`(id) 合并进 `data/`，新发布的稿子自动入库，不需要改代码；
- 列表页候选链接会先按**发布日期从新到旧排序**再按 `max` 截断 —— 即使某个栏目页不是按时间倒序，
  新条目也不会被旧稿挤出配额。

### 发布时间与活动时间是两回事

页面上一律分开展示，抓取侧也分开解析，别让它们互相污染：

| | 字段 | 来源 | 页面位置 |
|---|---|---|---|
| **发布时间** | `d` | 列表页日期 / 详情页 `pubdate` 等 meta / 正文首个**合理**日期 | 卡片右侧时钟、详情「发布时间」 |
| **活动时间** | `dt.tm` / `dt.ev` | 正文里带「活动时间 / 讲座时间 / 时间：」等标签的句子 | 详情「活动时间 / 开始时间」；「近期活动」视图按 `dt.ev[0]` 排序 |

规则：

- 发布时间**不允许是未来日期**（`parse_date(..., publish_context=True)`）：列表窗口里先出现的日期
  往往是讲座/讨论班的活动日，宁可留空显示「时间待定」，也不能当发布时间；
  若整段文本里有完整日期但被判为未来，脚本不会再退回「年月/月日」粗粒度解析（否则
  「2026年10月20日」会被截成 10 月 1 日混进发布时间）。
- 活动时间只从**带标签**的句子里取（`NOT_A_TIME_LABEL` 排除了「发布时间/更新时间/报名截止/答辩/考试」等），
  并且要求值里确实含月日或时刻，避免把「参会人数：10人」之类当时间。
- 「近期活动」视图的卡片显示的是**活动开始时间**（前缀「活动」），普通列表卡片显示**发布时间**；
  悬停都能看到 `title` 提示（发布时间 / 活动开始时间）。

### 微信公众号为什么是这种接法

微信公众号**没有公开的文章列表接口**：搜狗微信搜索有反爬、公众平台接口需要认证服务号、
新榜/清博之类要付费，所以“自动枚举某个官号的全部历史文章”做不到；但**单篇文章是可以公开读取的**。
因此脚本用了**三条**路，产出的 item 结构完全一致（`dt.sg = "wechat"`）：

1. **自动发现**（`fetch_campus.py`）：学校官网/新闻网经常链接或转载自己官微的文章，脚本会把这些
   `mp.weixin.qq.com/s/...` 链接一并抓下来，公众号名（如「浙江大学」「上海交大电院」）
   直接当来源名入库；
2. **手工清单**（`fetch_campus.py` + `fetch_wechat.py`）：
   `_work/wechat/wechat-<校区>.txt` 一行一个文章链接（`#` 开头是注释），两个脚本都会读；
3. **后台接口**（`fetch_wechat.py`，需 cookies）：用**你自己**登录的微信公众平台 cookies
   调 `searchbiz` 搜号 + `appmsg` 拉历史文章列表，按号**成批**取回推文。

> 第 3 条是唯一能"按号枚举"的路，但有两个前提：① 需要 cookies（几天过期）；
> ② `appmsg` 有**账号级限流**（`ret=200013`，新登录账号几乎必中，需等数小时至 1 天）。
> 详见 `docs/wxmp公众号接入.md`。
>
> 第 3 条**默认不在云端跑**（`cloud_update.py` 需要显式 `--with-wechat`）：
> cookies 属账号凭据、wxmp 依赖链与「阿里云侧零依赖」冲突。推荐的组合是
> **官网走云端定时、公众号走本机**，两者写同一份 `data/<校区>.json`。

### 登记公众号（把某个号「加进信息源」）

`fetch_campus.py` 顶部有一份登记名单，目前浙大已登记 14 个官微：

```python
WECHAT_ACCOUNTS = {
    "zju": [
        "浙大灵韵音乐剧社", "竺院团学汇", "ZJU星弦幻协", "ZJUPES", "浙里等宁",
        "浙大竺院人", "浙大魔协", "浙大体育与艺术", "浙江大学本科招生",
        "浙江大学CC98论坛", "浙江大学物理学院", "浙江大学学生会",
        "浙江大学校友总会", "浙浙小喇叭",
    ],
    "sjtu": [], "xjtu": [],
}
```

> `fetch_wechat.py` 里另有一份**要真正去抓的公众号清单**（`WECHAT_CONFIG` +
> `_work/wechat/wxmp-accounts-<校区>.json`），目前浙大 14 / 上交 16 / 西交 12 = 42 个号。
> 两份名单作用不同：`fetch_campus.py` 那份只管「官网里出现的文章要不要放行」，
> `fetch_wechat.py` 那份是「主动去拉历史文章列表的号」。

登记之后有两件事会变：

1. **账号过滤放行**：默认只收名字里含「浙大 / 浙江大学」的号，像 `ZJUPES`、`竺院团学汇`、
   `浙里等宁`、`浙浙小喇叭`、`ZJU星弦幻协` 这种不含校名的号，登记后才会被收录；
2. **页面上可见**：还没抓到内容的已登记公众号，会在「信息来源」抽屉里以「已登记公众号 · N 个待接入」
   的虚线胶囊列出来 —— 一眼就知道哪些号还缺内容。

**给已登记的号补内容**有两种办法：

- 在学校官网/新闻网里出现它的文章链接时自动收录（脚本每轮都会去这些页面找）；
- 把你的文章链接写进 `_work/wechat/wechat-<校区>.txt`（一行一个，`#` 开头是注释），然后重跑
  `python fetch_campus.py --campus zju`。脚本会自动读这个文件，不需要额外参数；
  也可以用 `--wechat-file 别的文件` 指定其它清单。

> 清单里的链接会逐篇抓取，公众号名、标题、发布时间、正文都从文章页面里取，
> 所以只要链接有效就能入库；失效或已删除的文章会被自动跳过。

### 只增不减与来源状态

抓取是**追加式**的：

- 每轮抓到的条目按 `i`(id) 合并进 `data/<校区>.json`，**已有条目不会被删除**：同一篇稿子标题/正文更新了就覆盖，
  官网后来撤下的旧通知仍然留在库里。`--replace` 是唯一的例外（会把整个校区的条目换掉，一般别用）。
- **90 天保留期**：合并之后会自动清除**发布时间距今超过 90 天**的条目（`refresh.py` 里的
  `RETENTION_DAYS`，改成 0 可关闭）；生成页面（`--build-only` 也一样）时会把 `data/*.json` 里
  超期的历史条目顺手清掉并重算来源统计。发布时间未知的条目**不参与清除**，
  与页面上「时间未知的通知不参与时间筛选」是同一条原则；页面端也在加载数据时做了同样的过滤兜底。
- `data/<校区>.json` 里记录 `append_only: true` 与 `last_import {added, updated, items, at}`，
  页面的「信息来源」和「数据概览」会显示「最近一轮新增 N 条」。
- 每个来源的状态存在 `_work/registry-<校区>.json`，并合并进 `data/<校区>.json` 的 `sources[]`，
  页面据此显示状态徽标：

| status | 页面徽标 | 含义 |
|---|---|---|
| `ok` | 最近更新 | 本轮抓取成功，且抓到新条目 |
| `no_recent` | 无新内容 | 本轮抓取成功，但没有新条目（官网这轮没发新东西） |
| `failed` | 采集失败 | 列表页请求失败；保留上一轮状态和已有条目 |
| `pending` | 待接入 | 已登记但从未取到内容（主要是公众号） |

- 来源注册表**同样只增不减**：某一轮没抓到的来源不会被从列表里抹掉，只更新它的状态，
  所以页面上永远能看到「这个来源存在、现在是什么状态」。
- 「数据概览」里会按状态汇总各有多少个来源。

### 抓取的礼貌与边界

- 同一主机两次请求至少间隔 1.2 秒（`--delay` 可调），失败重试 2 次；
- 各站都没有 robots.txt（404），脚本只抓公开页面，只存标题/时间/摘要/正文摘录与原文链接；
- 结果先落到 `_work/items-<校区>.json` 供检查，再经 `refresh.py` 的写入保护写进 `data/`
  （备份、原子写入、统计重算都照旧）；
- 跨栏目重复的稿子会按标题去重（同一篇稿子常同时挂在「要闻」和「综合」下）。

## 1.5 用 `--import` 导入自建信息源

如果 `fetch_campus.py` 里的来源不够，或者你想自己抓别的内容，把抓到的内容整理成一个 JSON 文件，
然后：

```bash
python refresh.py --campus zju --import my-items.json            # 按 id 合并进 data/zju.json
python refresh.py --campus zju --import my-items.json --replace  # 整校区替换成这一份
python refresh.py --campus zju,sjtu --import my-items.json       # 同样的数据写给多个校区
```

导入文件的两种写法都认：

```json
[ { "i": "...", "t": "...", ... }, { ... } ]          // 直接是数组
{ "items": [ { "i": "...", ... } ] }                  // 或者包一层
```

每条通知**最少**要有 `i`（唯一 id）和 `t`（标题）；`s`（来源名）、`u`（原文链接）、`d`（发布时间）、
`c`（分类）强烈建议都填，缺了会按默认值补齐并在命令输出里提示（缺分类一律归入「校园动态」）。

零基础的最小示例 —— 直接拿 `build/reports/sample-campus-items.json` 改：

```bash
python refresh.py --campus zju --import build/reports/sample-campus-items.json
```

导入成功后命令会打印：

```
✓ E:\project\thu-know\data\zju.json  (3 条，新增 3 / 更新 0 / 2 KB)
✓ E:\project\thu-know\index.html
  校区 sjtu, thu, xjtu, zju · 共 1327 条 · 2.73 MB
```

`data/zju.json` 里的 `sources` / `groups` / `category_totals` 会**按导入的 items 自动重算**，
所以页面顶部的「微信公众号 · N」「M 个信息来源」一定是准的，不需要你手算。

### 自己写抓取脚本

任何能产出上面那个 JSON 的东西都行。下面是一个可以直接改的最小骨架（只依赖标准库）：

```python
#!/usr/bin/env python3
# -*- coding: utf-8 -*-
# fetch_my_source.py —— 把任意来源整理成 --import 能吃的文件
import json
import re
import urllib.request

UA = {"User-Agent": "Mozilla/5.0 (Windows NT 10.0; Win64; x64) Chrome/120.0.0.0 Safari/537.36"}
PAGES = [
    # (链接, 标题, 发布时间, 分类, 来源名, 来源分组)
    ("https://www.example.edu.cn/info/1002/12345.htm", "关于某某的通知", "2026-10-08T10:00:00+08:00",
     "校园动态", "某某学院官网", "official"),
]


def to_text(html):
    """把网页压成纯文本摘录。"""
    html = re.sub(r"(?s)<(script|style).*?</\1>", " ", html)
    html = re.sub(r"<[^>]+>", " ", html)
    return " ".join(html.split())


items = []
for url, title, published, category, source, group in PAGES:
    with urllib.request.urlopen(urllib.request.Request(url, headers=UA), timeout=20) as resp:
        html = resp.read().decode("utf-8", "replace")
    items.append({
        "i": url,                      # 唯一 id：直接用链接最省事（重复导入时按它覆盖）
        "t": title,
        "s": source,                   # 显示在卡片右下角
        "si": "my_source",             # 来源标识，同来源保持一致
        "d": published,                # ISO8601；没有发布时间就留空，页面会显示「时间待定」
        "u": url,                      # 「阅读原文」的跳转地址
        "c": category,                 # 必须是 13 个分类之一，见 1.8
        "g": "information",            # activity(活动) / information(通知)
        "dt": {
            "tx": to_text(html)[:520], # 正文摘录（页面只放前 520 字）
            "og": source,
            "sg": group,               # wechat / official，决定它归入哪个来源筛选
        },
    })

with open("my-items.json", "w", encoding="utf-8") as fh:
    json.dump(items, fh, ensure_ascii=False, indent=2)
print("写好", len(items), "条 → my-items.json")
```

跑 `python fetch_my_source.py`，再 `python refresh.py --campus zju --import my-items.json` 即可。
以后每次重新抓完再 import 一次就行（按 `i` 覆盖旧条目，不会重复）。

## 1.8 `data/<校区>.json` 字段规范

### 顶层

| 字段 | 作用 | 必填 |
|---|---|---|
| `items` | 通知数组，页面的全部内容 | **是** |
| `campus` | 校区 key（实际以文件名为准） | 建议 |
| `campus_name` | 显示名；切换栏自动补充新校区时用它 | 建议 |
| `scraped_at` | 「数据概览」里的「页面内置数据抓取于」 | 建议 |
| `site_last_sync` | 页脚「数据同步时间」 | 建议 |
| `interval_minutes` | 上游同步间隔，仅记录 | 否 |
| `total_all` / `fetched` / `truncated` | 上游总数 / 本次条数 / 是否被 `--limit` 截断 | 否 |
| `import_source` | 由哪个文件导入的 | 否 |
| `fetch_warnings` | 抓取/导入的告警，只打到终端 | 否 |
| `sources` | 来源清单，驱动「信息来源」抽屉的胶囊 | 建议 |
| `groups` | 来源分组统计，驱动顶部「信息来源」勾选框后面的数字 | 建议 |
| `category_totals` / `intent_totals` | 统计留档（当前页面未使用） | 否 |

手改 `items` 之后记得重算统计（`--import` 会自动做）：

```python
import json, refresh
p = json.load(open("data/zju.json", encoding="utf-8"))
p["items"] = [...]                                    # 你改过的条目
p.update(refresh.recompute_stats(p["items"]))         # 重算 sources / groups / 分类统计
json.dump(p, open("data/zju.json", "w", encoding="utf-8"),
          ensure_ascii=False, separators=(",", ":"))
```

### `items[]` 里的一条通知

| key | 含义 | 必填 | 缺省行为 |
|---|---|---|---|
| `i` | 唯一 id（去重键，重复导入按它覆盖） | **是** | 缺失直接报错 |
| `t` | 标题 | **是** | 卡片会空着 |
| `s` | 来源名（公众号 / 部门） | 建议 | 卡片右下角空着 |
| `si` | 来源 id | 否 | — |
| `d` | 发布时间，ISO8601 | 建议 | 退回 `dt.ev[0]`；都没有则显示「时间待定」且时间筛选不隐藏它 |
| `u` | 原文链接 | 建议 | 「阅读原文」按钮隐藏 |
| `c` | 分类，13 个之一 | **是** | 缺失归入「校园动态」 |
| `g` | `activity`（活动）/ `information`（通知） | 否 | `information` |
| `en` / `ens` | 英文标题 / 英文来源 | 否 | 中英切换时不显示英文 |
| `dt` | 详情对象，见下表 | 否 | 详情弹窗显示「暂无更详细的正文」 |

### `dt`（详情）

| key | 含义 | 页面上显示为 |
|---|---|---|
| `su` | 摘要（≤240 字） | 「内容摘要」 |
| `tx` | 正文摘录（≤520 字，纯文本） | 「正文摘录」 |
| `tm` | 活动时间的文字描述 | 详情里的「活动时间」 |
| `lo` | 地点 | 「活动地点」 |
| `og` | 主办方 | 「主办方」 |
| `dl` | 报名 / 截止说明 | 「报名 / 截止」 |
| `ev` | `[开始时间, 结束时间]`，ISO8601；只有开始时间也行 | 「开始时间」，并让该条进入「近期活动」视图 |
| `at` | 附件名数组（≤8 个） | 「相关附件」 |
| `sg` | 来源分组：`wechat` / `official` / `other` | 决定它归入哪个来源筛选 |

| 分类 | 左边导航所在分组 | 色调 tone | 图标 |

| 文体活动 | 活动 | lilac | ticket |
| 社团公益 | 活动 | peach | users |
| 讲座活动 | 活动 | water | presentation |
| 学习成长 | 活动 | amber | book |
| 实习就业 | 活动 | rose | briefcase |
| 交流访学 | 活动 | slate | plane |
| 校园动态 | 通知 | amber | landmark |
| 学术科研 | 通知 | water | flask |
| 院系资讯 | 通知 | lilac | building |
| 生活资讯 | 通知 | peach | coffee |

**左侧分类导航里不会有入口**。想加正式分类见 2.5。

### `sources` / `groups` 的形状

```json
"sources": [
  { "name": "浙大官微", "source_group": "wechat",   "count": 12 },
  { "name": "浙大官网", "source_group": "official", "count": 5  }
],
"groups": [
  { "id": "wechat",   "sources": 1, "count": 12 },
  { "id": "official", "sources": 1, "count": 5  }
]
```

`groups` 里 `id` 只能是 `wechat` / `official` / `other`；`sources` 是来源个数，`count` 是通知条数。
页面顶部的两个勾选框显示的就是 `groups` 里的数字。

## 1.9 排错表

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 页面还是「X 还没有接入信息源」 | 数据文件里 `items` 为空；或改完 JSON 忘了重新生成 | `python refresh.py --build-only` |
| 某个校区灰掉、点了弹提示 | 这个 key 登记了但没有对应的 `data/<key>.json` | 补数据文件，或从 `CAMPUS_ORDER` / `CAMPUS_NAMES` 里移除 |
| 跑 `refresh.py --build-only` 直接报 JSON 错 | 某个 `data/*.json` 不是合法 JSON（手改时漏了逗号/引号） | 报错里会指出文件；用编辑器校验，或从 `data/<key>.json.bak` 恢复 |
| 导入报「每条通知都必须有 i(id) 字段」 | 有条目缺 `i` | 给每条一个稳定唯一的 id（用链接最省事） |
| 导入报「未知校区」 | `--campus` 的值不在 `CAMPUS_LABEL` 里 | 用 `thu` / `zju` / `sjtu` / `xjtu`，或先按 1.7 登记 |
| 来源筛选后面的数字是 0，但列表里有卡片 | `groups` 没重算 | 重新 `--import`，或按 1.8 跑 `recompute_stats` |
| `fetch_campus.py` 报某来源 0 条 | 该站改版/栏目页被 WAF 拦（返回「提示信息」页）/URL 已失效 | 打开那个 URL 确认；换一个栏目页，或把该行从 `SOURCES` 里删掉 |
| 抓到的时间不对（抓到的是「发布时间」） | 正文里没有规范的「活动时间：」 | 正常，`dt.tm` 只在能确认时才写；`d` 用的是发布/页面日期 |
| 公众号文章一条都没抓到 | 页面里的 `mp.weixin.qq.com` 链接失效，或文章已被删除 | 属正常损耗；用 `--wechat-file` 补几篇有效链接 |
| 中文在终端里显示成乱码 | Windows 控制台是 GBK | 不影响数据；`fetch_campus.py` / `refresh.py` 已把输出改成 UTF-8 |
| 卡片显示「时间待定」 | 这条没有 `d`，`dt.ev[0]` 也是空 | 补 `d` 或 `dt.ev` |
| 分类跑到最后、左边没有入口 | `c` 不是 13 个分类之一 | 改成标准分类，或按 2.5 正式加一个 |
| `python refresh.py --campus thu` 报 403 / 404 | 上游限流，或该校区上游没有这个路径 | 等一会儿重试；`--campus zju` 之类本来就是没有接口的，会直接跳过 |
| 想删掉某个来源的通知 | — | 用 `--replace` 导入一份不含它的 items；或改完 JSON 再 `--build-only` |

# 第二部分：页面风格

## 2.1 只改 `template.html`

`template.html` 结构：**第 10–379 行是整套 CSS**，中间是 HTML 骨架，**最后一段 `<script>` 是全部交互逻辑**
（分类配置、图标表、数据整理、渲染、弹窗、主题、深链都在里面）。

改完一律：

```bash
python refresh.py --build-only
```

> ⚠️ 不要直接编辑 `index.html`：它是产物，下次生成会被整段覆盖。
> 想验证某个改动的效果，可以只改 `template.html` 再 `--build-only`，然后刷新浏览器。

## 2.2 颜色令牌总表（`:root`，第 14–45 行；暗色版在 `html[data-theme=dark]`，第 46–73 行）

| 变量 | 影响哪里 | 浅色当前值 |
|---|---|---|
| `--background` | 页面底色 | `#faf8f6` |
| `--foreground` | 正文文字 | `#2b2431` |
| `--card` / `--card-foreground` | 卡片、顶栏、下拉框的底色/文字 | `#ffffff` / `#2b2431` |
| `--muted` | 次级底色（统计块、附件、页脚分隔处） | `#f3efec` |
| `--muted-foreground` | 次要文字（时间、来源、页脚、占位说明） | `#6f6575` |
| `--border` | 分隔线、面板描边、次级按钮边 | `#e7e1de` |
| `--input` | 搜索框描边、下拉框悬停描边 | `#988aa3` |
| `--ring` | 键盘聚焦外框（`:focus-visible`） | `#a779bb` |
| `--primary` / `--primary-foreground` | 主色：链接高亮、选中态、主按钮、「最新」圆点、高亮 `mark` | `#86539b` / `#fffaf7` |
| `--accent` / `--accent-foreground` | 主色的浅底（悬停底、摘要块、数字胶囊） | `#efe3f5` / `#613571` |
| `--danger` | 预留（当前没有规则使用） | `#b3455c` |
| `--shadow-sm/md/lg` | 卡片静止 / 悬停 / 弹窗阴影 | — |
| `--font-sans` / `--font-numbers` | 正文字体 / 数字与等宽字体 | — |
| `--ease-out` | 全局缓动曲线 | — |

⚠️ 浅色和暗色是**两套独立的变量**，改一个颜色要两边都改，否则切到暗色会露馅。
`--muted-foreground` 和 `--input` 当前是按 WCAG 对比度调过的（前者在各种底色上都 ≥4.8:1，后者 ≥3:1），
往浅里调会影响可读性。

## 2.3 换主色调（以「紫 → 蓝」为例）

改 5 个变量 × 2 套主题，再改 2 处品牌图形：

```css
/* :root 里 */
--primary:#2f6fb5;  --primary-foreground:#f7fbff;
--accent:#e3eefb;   --accent-foreground:#1d4a7a;
--ring:#5b93cf;

/* html[data-theme=dark] 里 */
--primary:#9cc7f0;  --primary-foreground:#16324f;
--accent:#2c4661;   --accent-foreground:#dcecff;
--ring:#bcdcff;
```

品牌图形两处（都在 `template.html` 里，颜色是写死的）：

1. **浏览器标签页图标**：`<link rel="icon" href="data:image/svg+xml,...fill='%2386539b'...">`
   —— 把 `%2386539b` 改成 `%232f6fb5`（URL 编码里的 `#` 写成 `%23`）。
2. **左上角吉祥物**：`.brand-mascot` 里的两个渐变色标
   `<stop offset="0" stop-color="#a56ebd"/><stop offset="1" stop-color="#6b3d8c"/>`
   —— 改成深浅两档蓝，例如 `#5b93cf` / `#23558c`。

改完 `--build-only`，切到暗色再确认一遍。

## 2.4 8 色 tone 体系：改色 / 加色

每个分区（`<section class="notice-section" data-tone="xxx">`）通过 `data-tone` 取一套 4 个变量：

| 变量 | 用途 |
|---|---|
| `--tone-ink` | 分区标题文字、卡片悬停描边、左侧色条、勾选框选中色 |
| `--tone-tint` | 悬停底色（分类导航按钮悬停、「展开全部」悬停） |
| `--tone-surface` | 分区面板底色 |
| `--tone-edge` | 分区描边 |

现有 8 个：`water` `lilac` `peach` `amber` `ochre` `rose` `iris` `slate`。

**改某个色调**：改 `:root` 里 `--tone-<名字>-ink/tint/surface/edge` 四个值和暗色块里的同名四个值。

**加一个新色调**（可复制现成一组改）：

```css
/* :root 里加 4 个 */
--tone-mint-ink:#2f6f5e; --tone-mint-tint:#d6f0e6; --tone-mint-surface:#f0faf6; --tone-mint-edge:#cfe8de;
/* html[data-theme=dark] 里也加 4 个 */
--tone-mint-ink:#a8e6d0; --tone-mint-tint:#3c5c53; --tone-mint-surface:#2c3f3b; --tone-mint-edge:#4a6b61;
/* 在 [data-tone=...] 那一片最后补一行 */
[data-tone=mint]{--tone-ink:var(--tone-mint-ink);--tone-tint:var(--tone-mint-tint);--tone-surface:var(--tone-mint-surface);--tone-edge:var(--tone-mint-edge)}
```

然后把某个分类的 `tone` 指过去（见 2.5）。没定义 `data-tone` 的元素会退回
`TONE_FALLBACK = ["lilac","peach","water","amber","rose","slate","iris","ochre"]` 按顺序轮着取。

## 2.5 分类：改名 / 换色 / 换图标 / 加分类 / 调左右分组

分类表在脚本里的 `CATEGORY_META`（搜 `CATEGORY_META`）：

```js
var CATEGORY_META = [
  { name:"文体活动", tone:"lilac", icon:"ticket",       group:"activity",    short:"文体" },
  { name:"社团公益", tone:"peach", icon:"users",        group:"activity",    short:"社团" },
  ...
  { name:"校园服务", tone:"water", icon:"buoy",         group:"information", short:"服务" }
];
```

| 想做的事 | 改什么 |
|---|---|
| 改分类名 | `name`（`data/*.json` 里的 `c` 也要跟着改，两边必须完全一致） |
| 换颜色 | `tone` 改成 2.4 里的任一个名字 |
| 换图标 | `icon` 改成 `P` 表里的名字（见 2.6） |
| 调整它属于「活动」还是「通知」 | `group`：`activity` / `information`（决定点左侧大分组时是否包含它） |
| 改手机端导航上的短名 | `short` |
| 加一个新分类 | 在数组里加一项（`name` 唯一），再去 `renderClusters()` 的 `clusters[].cats` 里把名字加进对应分组 |

`renderClusters()` 里两个分组决定**左边导航**有哪些入口：

```js
var clusters = [
  { id:"activity",    label:"活动", tone:"peach", icon:"party",
    cats:["文体活动","社团公益","讲座活动","学习成长","实习就业","交流访学"] },
  { id:"information", label:"通知", tone:"water", icon:"megaphone",
    cats:["校园动态","学术科研","院系资讯","生活资讯","学业教务","奖助评优","校园服务"] }
];
```

> 加分类只改 `CATEGORY_META` 也能生效（正文会多一个分区），但**左侧导航不会出现入口**，
> 要两边都加才完整。

**导航上显示长名还是短名**：基础样式里有 `.cat-label-long{display:none}`，所以现在是短名
（文体 / 社团 / 讲座…）。想显示全名，把这一行改成 `display:inline`，再把 `@media (max-width:860px)`
里的那两行（`.cat-label-long{display:none}` / `.cat-label-short{display:inline}`）保持原样即可。

## 2.6 图标怎么加

图标都在脚本开头的 `P` 表里，值是 SVG 内部路径（用 `currentColor` 描边，跟着文字颜色走）：

```js
var P = {
  clock:'<circle cx="12" cy="12" r="10"/><polyline points="12 6 12 12 16 14"/>',
  ...
};

function ic(name, size) {   // ic("clock", 16) → <svg viewBox="0 0 24 24" width="16" ...>
```

加一个图标：从 Feather / Lucide 之类的地方复制 24×24 的路径，塞进 `P` 表：

```js
  rocket:'<path d="M4.5 16.5c-1.5 1.26-2 5-2 5s3.74-.5 5-2c.71-.84.7-2.13-.09-2.91a2.18 2.18 0 0 0-2.91-.09z"/><path d="m12 15-3-3a22 22 0 0 1 2-3.95A12.88 12.88 0 0 1 22 2c0 2.72-.78 7.5-6 11a22.35 22.35 0 0 1-4 2z"/>',
```

然后 `icon:"rocket"` 或 `ic("rocket", 16)` 就能用。图标表里的名字是唯一键，别重名。

## 2.8 字体与字号

```css
--font-sans:"Geist","Inter",-apple-system,BlinkMacSystemFont,"Segoe UI",Roboto,"PingFang SC","Hiragino Sans GB","Microsoft YaHei",sans-serif;
--font-numbers:"Geist Mono",ui-monospace,SFMono-Regular,Menlo,Consolas,monospace;
```

- 正文基准在 `body{font-size:16px;line-height:1.6}`（想整体放大缩小，改这里最省事）。
- 这两个字体栈是「本机有就用，没有就退回系统字体」，**不联网加载字体**（页面要能离线双击打开）。
  想用自托管字体可以加 `@font-face`，但会把单文件站点拆成多文件，需要自己权衡。
- 数字（条数、百分比）用 `--font-numbers`，改它会影响所有计数胶囊的观感。

## 2.9 暗色模式

- 配色覆盖写在 `html[data-theme=dark]{ ... }` 一整块里（第 46–73 行），改暗色**只改这一块**。
- 切换按钮：`#theme-dark` / `#theme-light`，用 `html[data-theme=dark] .theme-to-dark{display:none}`
  这种方式让当前模式对应的按钮隐藏。
- 用户选择记在 `localStorage` 的 **`thu-know-theme`**；其它偏好（列数、排序、语言）记在
  **`thu-know-prefs`**。清掉这两个键就能恢复默认。
- 想默认就是暗色：把 `<html lang="zh-CN" data-theme="light">` 改成 `data-theme="dark"`。
  注意脚本启动时如果 localStorage 里已有用户选择，或系统 `prefers-color-scheme: dark`，会覆盖这个默认值。
- 改暗色时重点核对：`--card` 与 `--background` 的层次、`--border` 是否还看得见、
  8 个 tone 的 `-ink`（文字色）在 `-surface`（底色）上是否够清楚。

## 2.13 改样式的注意事项

1. **浅色/暗色是两套变量**，只改一套，另一套就会露馅。
2. **`[hidden]{display:none!important}` 这条兜底别删**。搜索框的「×」、详情里的英文标题、
   「阅读原文」按钮都靠 `hidden` 属性切换；作者样式里的 `display` 会盖掉浏览器默认的 `[hidden]` 规则。
3. **`--cols` 不是写在 CSS 里的**，是脚本运行时按「每行列数」下拉设到容器上的内联变量，
   所以改列数要去 HTML 的 `<option>` 和脚本的 `state.cols`，不要往 `.notice-grid` 里写死列数。
4. 改 `.notice-block` 的高度/行数时要顺带看一眼悬停色条（`::after` 的 `top:14px;bottom:14px`）和
   「最新」圆点（`::before` 的 `top:9px;right:9px`）是否还对得齐。
5. 字号改小要同时检查 `.board-empty`、`.src-chip`、`.stat-tile` 这些弹窗里的元素，
   它们各自写死了字号。
6. 新增 CSS 尽量用现成的变量（`var(--primary)` 之类），这样暗色模式和换色会自动跟着走。
7. 改完**一定重新生成**再看效果，别去编辑 `index.html`。
