## 1. 一句话说清这是什么

一个**单文件**校园信息聚合站，顶栏 **4 项**：**清华知道**（外链，点击直达 [pkuknow.cn/thu](https://pkuknow.cn/thu)）
+ **浙大 / 上交 / 西交**（由 `fetch_campus.py` 直抓各校**官网 + 职能部门**）。三校的**公开通知与活动**
合进一份数据，渲染进**一个** `index.html`（数据内嵌，双击即可打开，前端零依赖），打开默认落在**西交知道**。

- 成品：`index.html`（约 0.4 MB / 149 条，随抓取增长）
- 前身：本项目曾对照 pkuknow.cn 复刻、并一度扩到 32 栏（全部 985 除北大 / 人大），后按要求收敛回四栏；
  移出的数据与配置归档在 `_bak_1014/`
- 版权：所有内容归原作者/发布单位，仅作展示检索，**不得商用**

## 2. 系统全貌（三条链路）

```
            ┌─────────────────────────────────────────────────────────┐
            │ 数据源                                                   │
            ├─────────────────────────────────────────────────────────┤
清华        │ 外链：本站不抓取，顶栏项直接跳到 pkuknow.cn/thu         │
浙大/上交/西交│ 官网 + 职能部门（fetch_campus.py 直抓）                  │
公众号(可选) │ 微信公众平台后台接口（需你本人登录 cookies，不稳定）      │
            └─────────────────────────────────────────────────────────┘
                              │
          refresh.py / fetch_campus.py / fetch_wechat.py
                              │  按 id 合并、90 天保留期、写入前备份
                              ▼
                    data/<校区>.json  ← 两条链路的共同产物
                              │
                     refresh.py --build-only
                              ▼
                     index.html（成品）  ──►  EdgeOne Pages（公网）
```

| 链路 | 脚本 | 稳定性 | 产物 |
|---|---|---|---|
| **外链（清华）** | 无（`template.html` 里 `ext` 字段） | — | 无（顶栏项指向 pkuknow.cn/thu） |
| **官网（三校）** | `fetch_campus.py` | 稳定（20 个源） | `data/{zju,sjtu,xjtu}.json` |
| **建页** | `refresh.py --build-only` / `cloud_update.py` | 稳定 | `index.html` |
| **公众号** | `fetch_wechat.py` | **不稳定**（账号级限流 `ret=200013`） | 追加进同一份 json |

> **关键设计**：官网链路稳定、公众号链路不稳定，两者**只往同一份 `data/<校区>.json` 追加**，
> 所以任何一条断了都不影响另一条。默认**只跑官网**，公众号要显式 `--with-wechat` 才跑。

## 3. ⚠️ pkuknow.cn 上游 403：会话握手机制（2026-10 新增，必读）

> 当前四校的 `CAMPUS_PREFIX` 都是 `None`（清华是外链、三校走官网抓取），所以这条上游链路
> **平时用不到**。本节描述的能力仍保留在 `refresh.py` 里 —— 日后若某校恢复上游聚合接口，
> 在 `CAMPUS_PREFIX` 登记前缀即可启用，届时按下面的说明排查即可。

**症状**：

```
✗ thu 抓取失败：请求失败 https://pkuknow.cn/thu/api/notices?...: HTTP Error 403: Forbidden
```

**根因**（不是封 IP、不是 UA）：pkuknow.cn 现在要求**先建立读取会话**才能读 API。
直接请求会返回：

```json
{"code":"READ_SESSION_REQUIRED","scope":"missing_session","error":"会话已更新，请刷新页面后再试。"}
```

同时 `Set-Cookie: __Host-pku_read_guest=<uuid>.<ts>.<hmac>`。带上这个 cookie 重发，才返回 200。

**已内置的修复**（`refresh.py`，**无需任何额外配置**）：

- 模块级 `http.cookiejar.CookieJar()` + `urllib` opener，自动存/带 cookie；
- `prime_session()`：抓取前先访问一次 `https://pkuknow.cn/thu` 拿到 cookie；
- `get_json()`：若响应体出现 `READ_SESSION_REQUIRED`，或请求抛异常，
  自动**重新握手**（换新 cookie）后再试，最多 4 次。

**换机器 / 换 IP / 隔很久再跑，都不会再 403。** 若将来又出现 403，先看响应体：
- 是 `READ_SESSION_REQUIRED` → 会话问题，`refresh.py` 会自动处理；
- 是别的（如 `AccessDenied` / Cloudflare 页）→ 才可能是封禁，另行处理。

## 4. 日常怎么跑

```bash
# ① 最常用：一条命令抓完官网链路 + 重建页面
python fetch_campus.py                # 抓浙大/上交/西交
python cloud_update.py                # 等价，且只输出一段摘要（推荐）

# ② 不联网，只用现有 data/*.json 重建页面（改样式后必用）
python refresh.py --build-only

# ③ 公众号（不稳定，按需，需本机有 cookies）
python fetch_wechat.py --campus zju
python cloud_update.py --with-wechat
```

**环境**：Python 3.8+，官网链路**只用标准库**，无需 `pip install`。
唯一例外是 `fetch_wechat.py` 的 API 模式需要 `wxmp`（只在真要抓时才 import）。

**写入保护**（重要）：抓取不完整时**默认不覆盖** `data/*.json`——列表页失败、
实际条数比目标少 2% 以上、上游 `total_all` 异常、或比上次缩水 10% 以上，都会保留旧数据。
确实要写残缺数据才加 `--allow-partial`。覆盖前自动留 `data/<campus>.json.bak`。

## 5. 怎么发布到公网

**结论：走腾讯 EdgeOne Pages，不要用阿里云 OSS 默认域名。**

背景（踩过的坑）：阿里云 OSS 对 2017-10-01 之后创建的桶，用默认域名 `*.aliyuncs.com`
访问 html 会**强制下载**（服务端注入 `Content-Disposition: attachment`），
改对象元数据、开静态托管都**无效**，官方要求绑**已备案**自定义域名。
Netlify 这类海外免费托管在大陆有 DNS 污染，也不可用。

EdgeOne Pages：免费额度（50 GB 流量/月、300 万边缘函数请求/月），
默认域名 `*.edgeone.app` **免备案即可直接渲染**（备案后国内节点更快）。

```bash
# 1) edgeone 控制台创建 API Token
# 2) 本机执行（会把 index.html 打 zip 上传并返回公网 URL）
python deploy/edgeone/deploy_edgeone.py --token <你的token>

# 自动化接法（抓取 + 发布一条龙）
python cloud_update.py && python deploy/edgeone/deploy_edgeone.py
```

> EdgeOne CLI 是 **Node 工具**，**跑不了阿里云 FC（Python 运行时）**，所以发布这一步放在本机。
> 阿里云 FC 只负责「抓取 + 写 OSS」，发布由本机 cron / 定时任务触发。

## 7. 文件红绿灯：哪些能删、哪些碰不得

| 类别 | 文件 | 能不能删 |
|---|---|---|
| 成品 | `index.html` | 删了 `python refresh.py --build-only` 重建 |
| 数据 | `data/*.json` | **不能删**（历史基线）；`*.bak` 可删 |
| 官网中间产物 | `_work/items-*`、`_work/registry-*`、`_work/run.log` | 可删，重跑重建 |
| 公众号中间产物 | `_work/wechat/wechat-items-*`、`wxmp-fakeid.json` | 可删 |
| **公众号凭据/名单** | `_work/wechat/wxmp-cookie-header.txt`、`wxmp-accounts-*.json`、`wechat-<校区>.txt`、`wechat-名称总表.txt` | **不能删**（手工维护，删了要重登/重写） |
| 官网补充源 | `_work/sources-<校区>.json` | **不能删**（当前项目还没有此文件） |
| 测试 | `tests/*.py` | **不能删**（回归基线） |
| 留档 | `build/reports/*`、`tools/oneshot/*` | 可删（仅追溯） |
| 模板/辅助 | `template.html`、`tools/dev/*` | 保留（改样式 / 排查用） |

`data/`、`_work/`、`build/` 都是**生成物**，删掉不损坏项目，重跑即重建——
但上表标红的**手工文件**例外。

**安全提醒**：`_work/wechat/wxmp-cookie*` 与 `wxmp-cookies.json` 是**你微信公众平台的登录凭据**。
已在 `.gitignore` 里排除，**永远不要提交或外发**。凭据几天就会过期，需重新登录获取。

## 9. 常见故障速查

| 现象 | 原因 | 处理 |
|---|---|---|
| `thu ... 403 Forbidden` | 会话未建立 | 已自动处理；若仍失败看响应体，见第 3 节 |
| 某校区页脚「数据同步时间」不前进 | 本轮该上游没有抓到新内容（正常） | 看「页面生成于」是否前进即可确认云端有跑 |
| `fetch_wechat.py` 报 `200013` | 微信账号级限流 | 正常，等数小时至 1 天；脚本会保留旧数据 |
| 某官网站点状态「采集失败」 | 站点改版 / 死链 | 在 `fetch_campus.py` 的 `SOURCES` 里更新地址 |
| 页面正文/日期不对 | 该站正文容器非标准 | 看 `refresh.py`/`fetch_campus.py` 的容器白名单，或看测试用例 |
| OSS 上访问 html 变成下载 | 默认域名强制下载 | 改用 EdgeOne Pages（见第 5 节） |
