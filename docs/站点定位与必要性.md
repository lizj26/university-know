# 站点定位与必要性

> 起因：一个质疑 —— 「合集接口拿不全文章、也没时效性。既然这个聚合站信息不全又过时，它有什么存在必要？」
>
> 本文逐条核对这个判断。**所有数字来自 2026-10-14 对 `data/shard/*.json` 与仓库配置的实测统计**，
> 命令与结果附在文末，可自行复现。

---

## 0. 一句话

**质疑针对的是「公众号链路」，而站点的地基是「官网链路」—— 两条腿共用一个 `index.html`，
但站点默认只跑官网，149 条在库数据里公众号链接是 0 条。**

所以「合集拿不全」受伤的不是这个站，是想加的那条支线。

---

## 1. 先纠正一个前提：本站不抓公众号

`docs/移交说明.md` 第 2 节的链路表写得很直白：

| 链路 | 脚本 | 稳定性 | 产物 |
|---|---|---|---|
| **外链（清华）** | — | — | 顶栏跳 pkuknow.cn/thu |
| **官网（三校）** | `fetch_campus.py` | **稳定** | `data/{zju,sjtu,xjtu}.json` |
| **建页** | `refresh.py --build-only` | 稳定 | `index.html` |
| **公众号** | `fetch_wechat.py` | **不稳定**（账号级限流 `ret=200013`） | 追加进同一份 json |

> **关键设计**：两条链路**只往同一份 `data/<校区>.json` 追加**，任何一条断了都不影响另一条。
> **默认只跑官网**，公众号要显式 `--with-wechat` 才跑。

`README.md` 与 `.github/workflows/update.yml` 的注释也都写着「**只抓网站内容，不抓公众号**
（`fetch_campus.py` 里 `kind=wechat` 的来源已全部移除）」。

**实测验证**：当前 149 条在库数据，来源全部是官网/职能部门，链接域名 **0 条 `mp.weixin.qq.com`**。

> 结论：把「本站」等同于「靠合集接口的公众号聚合站」，是**前提错位**。
> 公众号在本项目里是**可选支线**，从未成为地基。合集接口的缺陷伤不到地基。

## 3. 逐条核对「不全」与「过时」

### 3.1 「过时 / 没有时效性」—— **不成立**

| 检查项 | 结果 |
|---|---|
| 自动化 | Actions cron `0 1,4,14 * * *`，**每天 3 轮** |
| 最新条目 | 2026-10-11（浙大求是新闻）；多条 10-10（交大教务 / 西交教务 / 西交新闻） |
| 距今天 | **3 天** |
| 各源最新发布 | `zju_news` 10-11 · `sjtu_jwc` 10-10 · `xjtu_news` 10-10 · `xjtu_jwc` 10-10 |

**天级更新，不存在"过时"。** 页面上出现的 7 月条目是 **90 天保留期**的设计（可回溯），不是"没更新"——
最新条目就在最上面。

### 3.2 「信息不全」—— **部分成立，要分清是哪种不全**

| 层 | 是否成立 | 说明 |
|---|---|---|
| 正文只给摘要 | ✅ **成立** | 86% 截断到 **520 字**，要看全文得点链接 |
| 不含院系站点 | ✅ 成立 | 原 44 个学院站已移出，只留官网 + 职能部门 |
| 不含公众号 | ✅ 成立 | 见第 1 节 |
| 只留 90 天 | ✅ 成立 | 老于 90 天的条目自动清除（有意为之） |
| 条目被截条数 | ❌ 不成立 | 列表页**全量收录**，无 per-source 条数上限 |

**所以"不全"是真的，但指的是「摘要 + 范围」，不是「漏抓」。**

## 4. 那它到底解决了什么

没有这个站，要看一篇通知，你得：

1. 记住 / 收藏 **15 个域名**、3 所大学的入口
2. 逐个访问，找到各自的「通知公告」栏目
3. 逐条判断"这条跟我有没有关系"
4. 点进去读

有了这个站：**1 个页面 · 12 类标签 · 520 字摘要直读 · 90 天回溯 · 跨校切换（按需分片，不看的校不下载）**。

再看它实际抓到了什么（最新几条）：

## 5. 为什么在「官方通知」这件事上，官网反而比公众号重要

这是最关键的一点，也顺带回答了「为什么不惜代价去搞公众号」。

**公众号上的教务通知，是官网通知的转载版。** 实测佐证：上海交大教务处的通知页
（`feedback.sjtu.edu.cn`）正文末尾同时印着 **`Details: https://mp.weixin.qq.com/s/...`**
和 **「微信号：SJTUjwc」** —— 说明**发布源是业务系统/官网，公众号是排版后的阅读版**。

推论：

| | 官网（本站地基） | 公众号（可选支线） |
|---|---|---|
| 发布时机 | 业务系统里**即时**发布 | 需人工编辑推送，**是否转、何时转不由你定** |
| 事务性通知（考场/申报/选课） | **通常只在此** | 常常不转 |
| 抓取难度 | 稳定，20 个源 | 账号级限流，不稳定 |
| 时效 | **天级自动** | 取决于转载时间 |

**所以目标如果是「不错过通知」，该加固的是官网链路，公众号只是补充。**

## 6. 它的真实边界（不回避）

- **不是**公众号订阅替代品 —— 想看学院公众号动态，这里没有
- **不是**全文库 —— 86% 正文截断到 520 字（**可改**，见第 7 节）
- **不是**全量历史 —— 只留 90 天
- **不含**院系站点与就业/二手等生活信息

---

## 7. 真正值得做的三件事（都比继续死磕公众号划算）

| 方向 | 解决什么 | 代价 |
|---|---|---|
| **① 加推送渠道**（RSS / 每日邮件摘要 / 企业微信机器人） | 你真正的痛点是「**不能及时获知**」—— 这是**推送**问题，不是聚合问题。数据已在库，纯官网链路就能做 | 一个 cron + 一个推送脚本 |
| **② 把正文截断从 520 提到 2000+，或对重点分类抓全文** | 解决「信息不全」里最实的那一条 | 改一个常量 + 重跑 |
| **③ 补院系源 / 更多种子** | 扩大覆盖面（院系官网是稳定的，不是公众号） | 加源配置 |

> 注意 ③：院系官网**能抓**，但实测其内容是**行政团务**（换届 / 选拔 / 学代会），
> **不是活动招募** —— 详见第 8 节。扩源能提升「学生事务」覆盖，但补不上「学生活动」。

## 8. 补测：为什么「学生活动」这块，官网链路覆盖不到

> 触发：一句反驳 —— 「**官网平时就没有人会看，一般学生活动推送都以公众号推文形式呈现**」。
>
> **核对结论：这个判断成立，而且实测比预期更彻底 —— 学生活动的官网载体本身在萎缩。**

### 8.1 站点内容构成：41% 是「没人看的官样新闻」

| 类别 | 条数 | 占比 | 代表条目标题 |
|---|---|---|---|
| **新闻 / 综合**（新闻网） | **61** | **41%** | 《校长会见吉尔吉斯斯坦科学、高等教育和创新部部长》·《召开 2026 年度第三次二级单位书记院长例会》·《校发展委员会副主席一行访问南非》 |
| 职能通知（教务 / 研究生院 / 招生 / 学工 / 图书馆 / 国际） | 88 | 59% | 《2026 秋季学期游泳技能培训班通知》·《课程选拔测试考场安排》 |

「没人看」这句批评，**精确命中那 41%**。

### 8.2 决定性证据：学生活动的**入口**在公众号

| 证据 | 内容 |
|---|---|
| 交大国庆活动汇总（媒体转载） | 每项活动都写着「活动信息将发布在**上海交大学生联合会**公众号」「通过**学生体育总会**公众号报名」「关注社团工作部公众号**交大社总**」 |
| 西交团委官网自己的文章 `tuanwei.xjtu.edu.cn/passage?id=4765`（2026-10-04） | 「最佳团日」往期回顾的跳转链接是 **`https://mp.weixin.qq.com/s/...`** |

**连团委官网自己，都把活动内容指向公众号。**

### 8.3 更彻底的发现：团委官网在停更

| 站点 | 最新内容 | 状态 |
|---|---|---|
| `youth.sjtu.edu.cn`（交大团委） | **2025-12-23** | **停更近 10 个月**（本轮实时探测：HTTP 200 / 23.7 KB 静态页，`/tzgg.html` 可抓，但内容陈旧） |
| `tuanwei.xjtu.edu.cn`（西交团委） | 2026-10-04（文章） | 半活跃；首页列表模块停在 2024-02 |
| `sztz.zju.edu.cn`（浙大素质拓展平台） | 2026-10-10 | 活跃，但内容是「第二、三课堂**审核流程**」，不是活动招募 |
| `ccea.zju.edu.cn/19127`（浙大建工团委） | 2026-06-05 | 活跃，内容是换届 / 选拔 / 学代会 —— **行政团务** |

**所以「再加几个团委源就能覆盖学生活动」这条推论，被实测否定。**
问题不是「官网有活动但我们没抓」，而是**活动的发布主渠道已经迁走，官网侧在萎缩**。

### 8.4 那站点该砍什么、留什么

| 源类型 | 判断 | 处理 |
|---|---|---|
| 新闻网（41%） | 学生不看，且与公众号重叠但更晚 | **建议砍掉或降权** |
| 教务 / 研究生院 / 招生 / 学工 | 选课、考试、报名、火车票核验 —— **刚需**，且**只在官网** | **保留 —— 这才是站点真正的价值** |
| 素质拓展 / 就业 | 第二课堂、实习就业信息 | **建议补源**（浙大素拓更新到 10-10，可抓） |
| 学生活动 / 社团 | 主渠道在公众号 | **官网链路覆盖不到 —— 硬缺口** |

### 8.5 诚实结论

**站点覆盖的是「行政通知」，不是「学生活动」—— 这两件事此前被混为一谈了。**

- 诉求是「不错过教务 / 学工类通知」→ 站点有价值，且官网是唯一源
- 诉求是「看学生活动 / 校园生活推送」→ **官网链路给不了**。这不是抓取姿势问题，
  是**渠道本身已经不在官网了**，任何爬虫技巧都无法把答案从不存在的地方取出来

## 9. 判断标准：你的场景是什么

| 你的场景 | 这个站够不够 |
|---|---|
| 考研 / 申请 / 在校生，要**不错过官方通知** | ✅ **够**，而且官网是唯一权威源 |
| 想**被动收到提醒**（不想每天来刷） | ⚠️ 站点不推送 —— 做第 7 节 ① |
| 想读**原文全文** | ⚠️ 只看摘要 —— 做第 7 节 ② |
| 想看**学生活动 / 校园生活推送** | ❌ **硬缺口** —— 渠道本身已迁到公众号（见第 8 节实测） |
| 想做**通用信息聚合产品** | ⚠️ 需要差异化定位，纯搬运官网价值有限 |
