# 添加一所新大学

本文说明如何给站点**新增一个校区**（例如从现有的「浙大 / 上交 / 西交」再加一所「复旦」）。

处理口径与**上交 / 西交完全一致**：

- 只抓 **官网 + 各校职能部门**（新闻网 / 通知公告 / 教务 / 研究生院 / 招生 / 学工 / 科研 / 国际交流 这类
  「更常见的信息需求」），**不逐院系铺开学院站**，**不抓任何公众号内容**。
- 不写死代码：一所学校 = 在 `SOURCES` 里加**一组来源**配置，换个校区 key 即可复用全部逻辑。
- 抓到的东西按 id **只增不减**地并进 `data/<key>.json`，超过保留期（90 天）由 `refresh.py` 生成页面时清除。

> 一句话流程：**调研来源 → 写进 `SOURCES` → 登记校区名 → 本地抓一遍验证 → 加进定时任务**。
> 下面以新增「复旦（key = `fdu`）」为例，逐步走一遍。现成范例可直接参考
> `fetch_campus.py` 里 `zju` / `sjtu` / `xjtu` 三组配置（纯 HTML 列表，其中 `sjtu` 还示范了 `link_re`）。

## 0. 一共要动哪几个文件

| 文件 | 改什么 | 是否必须 |
|---|---|---|
| `tools/campus_roster.py` | 加一行 `(key, 中文全名, 显示名, 英文名, 上游前缀, 外链地址)` | ✅ 必须 |
| `fetch_campus.py` | `SOURCES` 里加一组来源（**核心**） | ✅ 必须 |
| `README.md` | 校区表格补一行（对外说明） | 建议 |
| `docs/添加新大学.md` | 本文，加完后在末尾「已接入校区」补一行 | 可选 |

**其余五处配置不用手改**：`tools/campus_roster.py` 是全站唯一的名单真相源，
在它里面加好一行后跑 `python tools/register_campus.py`，会自动把校区同步进
`refresh.py`（`CAMPUS_PREFIX/LABEL/EN`）、`template.html`（`CAMPUS_NAMES/CAMPUS_ORDER`）、
`cloud_update.py`、`.github/workflows/update.yml`（`matrix.include`）、
`tools/refocus_data.py` 五处，幂等可反复跑。

> 若该校只想在顶栏放一个**外链**（本站不抓取，像「清华知道」那样），就在 roster 那一行把
> 「外链地址」填成目标 URL、并且**不给它配 `SOURCES`** 即可 —— 顶栏会渲染成新标签跳转链接。

## 1. 调研：找到「能稳定解析出文章」的列表页

一所要新增的学校，先摸清它的官网与职能部门。**判断标准只有一个：这个页面用脚本抓下来，
能不能解析出「标题 + 链接」**（有发布时间更好）。

### 1.1 先测官网连通性

```bash
cd /path/to/university-know
for u in "https://www.fudan.edu.cn/" "https://news.fudan.edu.cn/"; do
  echo -n "$u -> "; curl -sL -o /dev/null -w "%{http_code} %{url_effective}\n" -m 20 -A "Mozilla/5.0" "$u"
done
```

### 1.2 用抓取器本身的逻辑做「出链体检」

这是**最关键的一步**——不要靠肉眼看页面，直接用抓取器的解析函数跑一遍，
看每个候选页面能出多少条文章链接。存成 `_work/probe_fdu.py`：

```python
import importlib.util, re
spec = importlib.util.spec_from_file_location("fc", "fetch_campus.py")
fc = importlib.util.module_from_spec(spec); spec.loader.exec_module(fc)

CANDIDATES = [
    "https://news.fudan.edu.cn/",                 # 新闻网
    "https://jwc.fudan.edu.cn/",                  # 教务处
    "https://gs.fudan.edu.cn/",                   # 研究生院
    "https://zsb.fudan.edu.cn/",                  # 本科招生
]
for u in CANDIDATES:
    try:
        html, final = fc.fetch(u, delay=0.6, retries=1)
        bh = fc.host_of(final); rows = []
        for href, text, pos in fc.anchors(html, final):
            if not fc.is_article_link(href, bh):      # 通用「像不像文章」判断
                continue
            if len(re.sub(r"\s", "", text)) < 6:
                continue
            win = fc.strip_tags(html[max(0, pos-250):pos+250]).replace("\n", " ")
            rows.append((fc.parse_date(win) or "-", text[:30], href[:60]))
        print(f"{len(rows):3d} | {u}")
        for r in rows[:3]:
            print("      ", r)
    except Exception as e:
        print(f"ERR {u}: {e}")
```

```bash
python _work/probe_fdu.py
```

- **命中几十条、链接是 `.htm`/数字路径** → 标准列表页，直接用（`kind=list`，见第 2 步）。
- **命中 0 条，但浏览器里明明有内容** → 多半是**前端渲染**（Vue/React/Next），静态 HTML 里没有链接。
  两条路继续查（见 1.3）。
- **命中的是导航/栏目链接、不是文章** → 换该部门的「通知公告 / 新闻 / 动态」**栏目页**再测。
  栏目页地址通常能从部门首页导航里找到，形如 `/tzgg.htm`、`/xwzx/list.htm`、`/gzdt_xxx/list.htm`。

### 1.3 前端渲染站的两种破法

**（A）给它配一条 `link_re`。** 有些站点文章链接是 `?id=123`、`/post/detail/xxx` 这种，
通用判断认不出来。做法：抓下页面，看看文章链接长什么样，然后给这个来源写一条正则。

```bash
curl -sL -m 20 -A "Mozilla/5.0" "https://some.dept.fudan.edu.cn/news" \
  | grep -oE 'href="[^"]+"' | sort -u | head -30
# 找到规律后，写进来源配置的 "link_re"，例如：
#   "link_re": r"/post/detail/[A-Za-z0-9=_-]+"
#   "link_re": r"mid=26&v=informationview&id=\d+"
```

**（B）直接读它的 JSON 接口（`kind=json`）。** 若整站是前端渲染且**自带搜索/列表接口**，
比爬 HTML 更稳。做法：打开页面源码，找 `data-search-url`、`/api/...`、`fetch(...)` 之类的线索，
确认接口能返回 JSON，再用浏览器的「网络」面板或 `curl` 复现：

```bash
curl -sL -A "Mozilla/5.0" "https://site.example.edu/api/...?page=1&pageSize=20" | head -c 800
```

确认字段名（标题 / 链接 / 日期 / 摘要）后，按第 2.3 节配置 `kind=json` 来源。
（历史范例：港大（`hku`）曾这么接 —— 它的官网整站前端渲染，HTML 里一条文章链接都没有，
但官方搜索接口 `https://lead.hku.hk/api/en/search` 能直接返回 JSON。该校已移出，写法保留供参考。）

> **判断优先级**：HTML 列表页（最省事） > JSON 接口（前端渲染站最稳） > 放弃。
> 纯 JS 单页且**没有公开接口**的站点直接跳过——登记了也只会一直显示「采集失败」。

## 2. 写进 `SOURCES`

打开 `fetch_campus.py`，在 `SOURCES` 字典里加一个键（校区 key，小写英文字母），值是一组来源。
每个来源都是一个字典。**参考上交 / 西交的编排顺序：官网新闻在前，职能部门在后。**

### 2.1 标准 HTML 列表页（`kind=list`，绝大多数情况）

```python
    "fdu": [
        # ---- 官网新闻 / 通知 ----
        {"id": "fdu_news", "name": "复旦大学新闻网", "group": "official",
         "url": "https://news.fudan.edu.cn/", "kind": "list", "max": 15},
        {"id": "fdu_notice", "name": "复旦大学通知公告", "group": "official",
         "url": "https://www.fudan.edu.cn/tzgg.htm", "kind": "list", "max": 12},
        # ---- 职能部门 ----
        {"id": "fdu_jwc", "name": "复旦大学教务处", "group": "official",
         "url": "https://jwc.fudan.edu.cn/", "kind": "list", "max": 12},
        {"id": "fdu_gs", "name": "复旦大学研究生院", "group": "official",
         "url": "https://gs.fudan.edu.cn/", "kind": "list", "max": 12},
        {"id": "fdu_zsb", "name": "复旦大学本科招生", "group": "official",
         "url": "https://zsb.fudan.edu.cn/", "kind": "list", "max": 10},
        {"id": "fdu_xsc", "name": "复旦大学学生工作部", "group": "official",
         "url": "https://xsc.fudan.edu.cn/", "kind": "list", "max": 10},
    ],
```

**来源字段表（`kind=list`）：**

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | **全局唯一**的来源标识，建议 `<校区key>_<部门>`。入库条目的 `si` 就是它，**改名会导致历史条目对不上** |
| `name` | ✅ | 页面上显示的来源名 |
| `url` | ✅ | 列表页地址 |
| `kind` | ✅ | `list`（HTML 列表页）；`json`（见 2.3）；`wechat` 已停用 |
| `group` | 建议 | 目前一律填 `official`（页面按校区动态显示「XX官方网站」） |
| `max` | 建议 | 这个来源每轮最多取几条；不写则默认 15。**不必求多**，取最近 10~20 条即可 |
| `link_re` | 可选 | 自定义文章链接正则（见 1.3-A）；配了就只认它 |
| `enabled` | 可选 | `false` 可临时停用而不删配置 |

### 2.2 需要 `link_re` 的例子

```python
        {"id": "fdu_gs", "name": "复旦大学研究生院", "group": "official",
         "url": "https://gs.fudan.edu.cn/announcement/work", "kind": "list", "max": 10,
         "link_re": r"/post/detail/[A-Za-z0-9=_-]+"},
```

### 2.3 JSON 接口来源（`kind=json`，前端渲染站）—— 以港大接口为例（该校已移出，仅作写法示例）

```python
        {"id": "hku_press", "name": "香港大学新闻中心·新闻稿", "group": "official",
         "url": "https://www.hku.hk/press/press-releases/",          # 展示给人的页面地址
         "api": "https://lead.hku.hk/api/en/search?page=1&pageSize=40"
                "&section=newsroom&format=press-release",            # 真正的数据接口
         "kind": "json", "max": 20, "items_path": "result.items",
         "date_field": "newsDate", "summary_field": "standfirst"},
```

**来源字段表（`kind=json`）：**

| 字段 | 默认 | 说明 |
|---|---|---|
| `api` | 无 | 接口地址；给了它就用它取数，`url` 只作为**展示给用户看**的来源地址 |
| `items_path` | `items` | 条目数组在 JSON 里的路径，点号分层，如 `result.items` |
| `title_field` / `link_field` | `title` / `url` | 标题、链接字段名（链接是相对路径会自动补全） |
| `date_field` | `date` | 日期字段名，支持 `2026-10-11`、`11 Oct 2026`、`October 11, 2026` 等写法 |
| `summary_field` | `summary` | 摘要字段名（当正文摘录用） |
| `base` | 接口的 `scheme://host` | 相对链接的前缀 |

### 2.4 临时补来源 / 停来源（不改代码）

不想动 `fetch_campus.py` 时，可写一份 `_work/sources-<校区>.json`（格式见 `_work/sources.example.json`）：

- 同 `id` → 覆盖内置配置；
- 新 `id` → 追加一个来源；
- `"enabled": false` → 停用某个内置来源。

> 注意：`SOURCES` 里**删掉的来源**，其历史条目和注册表状态不会被自动清理（抓取器只增不减）。
> 要立刻把库收窄到新的来源集合，跑一次：
> ```bash
> python tools/refocus_data.py fdu      # 按当前 SOURCES 收窄；带 --dry-run 可只看预览
> ```

## 3. 登记校区（显示名 / 排序 / 语言）

### 3.1 `refresh.py`（由 `register_campus.py` 自动生成，无需手改）

```python
CAMPUS_PREFIX = {"thu": None, "zju": None, "sjtu": None, "xjtu": None, "fdu": None}
CAMPUS_LABEL  = {..., "fdu": "复旦知道"}                          # 中文显示名
CAMPUS_EN     = {..., "fdu": "FDU Know"}                         # 英文名（顶栏副标题）
```

- `CAMPUS_PREFIX` 填 `None` 表示**不经上游** —— 由 `fetch_campus.py` 直接抓官网。
  若某校日后有 pkuknow.cn 聚合接口，把前缀（如 `/thu`）填上即可启用上游抓取。
- `CAMPUS_LABEL` 会被写进 `data/<key>.json` 的 `campus_name`，也是页面顶栏的显示名。

### 3.2 `template.html`

```javascript
  var CAMPUS_NAMES = {
    thu: { zh:"清华知道", en:"THU Know", ext:"https://pkuknow.cn/thu" },   // ext = 外链校区
    ...,
    fdu: { zh:"复旦知道", en:"FDU Know" }
  };
  var CAMPUS_ORDER = ["thu", "zju", "sjtu", "xjtu", "fdu"];
```

- `CAMPUS_ORDER` 决定顶栏切换标签的**固定顺序**；不在表里的校区也会自动追加到末尾
  （名字用 `data/<key>.json` 里的 `campus_name`），但排不到指定位置，所以**建议显式登记**。

## 5. 接进定时自动更新

编辑 `.github/workflows/update.yml`，在 `jobs.fetch.strategy.matrix.include` 里加一条腿：

```yaml
          - campus: fdu
            command: python fetch_campus.py --campus fdu --workers 4 --delay 1.2 --no-build
```

- `--no-build`：这一腿只管抓自己那一个校区，**不重建页面**；页面由后面统一的 `build` job 重建并**只提交一次**。
- 抓取较慢 / 站点有 WAF 限流的学校，参考 `zju` 那条腿的写法（降并发、加 `--domain-delay`、加 `--rotate`）。
- 定时时间由文件顶部的 `cron` 控制（UTC，比北京时间早 8 小时）；三个时刻分别是北京时间 09:00 / 12:00 / 22:00。

> **上传提醒**：本机 `github.com` 被墙，仓库文件需要**手动上传**。
> 加完新校区后，需要上传的是：`fetch_campus.py`、`refresh.py`、`template.html`、
> `.github/workflows/update.yml`、`index.html`，以及新增的 `data/<key>.json`；
> 若本地已生成 `_work/registry-<key>.json`，一并上传（云端靠它延续来源状态）。
> 点开头的文件（`.github/...`、`.gitignore`）在文件管理器里默认隐藏，注意显示隐藏文件。

## 6. 常见问题

**Q：某个部门页命中 0 条，怎么办？**
A：先确认它是不是前端渲染（1.3）。能配 `link_re` 就配；能读 JSON 接口就用 `kind=json`；
两者都不行就**别收**——登记了也只会长期显示「采集失败」，不如让它空着。

**Q：抓下来一堆「在线课程平台」「更多」这种非文章链接？**
A：这是列表页把导航也混进来了。换该部门的**栏目页**（`/tzgg.htm`、`/xwzx/list.htm` 之类），
或者用 `link_re` 限定文章链接的形态。

**Q：日期显示不对 / 一片空白？**
A：抓取器的日期解析认中文与数字写法；英文写法（`11 Oct 2026`）已在 `parse_en_date()` 里支持。
都不匹配时条目时间会留空（显示「时间待定」），不影响收录。

**Q：站点老是 403？**
A：多半是 WAF 按 IP 限流。降并发（`--workers 2`）、加大间隔（`--delay 2.0`）、
对同一注册域名加聚合间隔（`--domain-delay 1.0`），必要时开 `--rotate` 让封锁窗口每轮落在不同来源上。
浙大（`zju`）就是典型案例，其定时任务里已带这些参数。

**Q：想撤销某所学校？**
A：从 `tools/campus_roster.py` 删掉那一行、跑一次 `python tools/register_campus.py`（五处配置一起收敛），
再从 `fetch_campus.py` 的 `SOURCES` 删掉那组来源、并归档／删除 `data/<key>.json` 即可。
其余逻辑通用，不受影响。（本轮把 32 栏收敛回 4 栏就是这么做的。）

## 一次加十几、几十所：批量路径

单所手工加（上面的流程）适合精调；**要一口气加十几、几十所，走批量路径**。
（本项目曾用这条路一次性接入过全部 985 高校，后来按要求收敛回四栏；方法本身照旧可用。）

```
① 改名单     tools/campus_roster.py       ← 加一行 (key, 中文全名, 显示名, 英文名, 上游前缀, 外链地址)
② 找来源     python tools/discover_sources.py        # 自动探测各校「官网 + 职能部门」可用栏目
③ 登记校区   python tools/register_campus.py         # 一次性同步 5 处配置 + 定时任务矩阵
④ 验证       python tools/refocus_data.py <key> --dry-run
             python tools/bench_update.py --campus <key>,<key>   # 真抓一遍看数据质量
```

### ① 名单：`tools/campus_roster.py`

全站唯一的「有哪些学校」真相来源。字段含义：

| 位置 | 含义 |
|---|---|
| `key` | `data/<key>.json` 的文件名，也是 `--campus` 的值 |
| 中文全名 | 来源名前缀（页面「信息来源」抽屉里显示） |
| 显示名 | 顶栏切换 / 来源分组标题上的名字，约定「简称 + 知道」 |
| 英文名 | 顶栏第二行 |
| 上游前缀 | 走 pkuknow.cn 聚合接口时的路径；`None` = 由 `fetch_campus.py` 直接抓官网 |

### ② 找来源：`tools/discover_sources.py`

自动做三件事：
1. 从学校主页导航里挑「新闻 / 通知 / 公告 / 要闻 / 动态」类栏目；
2. 按常见职能部门子域名（`news` `jwc` `gs` `yjs` `yz` `zsb` `job` `lib` `xsc` `gjc` `xygg` `tzgg` …）
   补一遍候选，每个子域试几个常见列表页路径；
3. **用 `fetch_campus.py` 自己的解析逻辑**验证这个页面能不能稳定给出「标题 + 链接 + 日期」，
   合格的才写进 `sources_more.py`（`fetch_campus.py` 导入时自动合并进 `SOURCES`）。

判定口径可以调（脚本顶部）：`MIN_LINKS`（最少几条）、`MIN_DATED`（带日期的比例下限）、
`MAX_PER_CAMPUS`（每校最多几个来源）、`SKIP_NAME`（不要的栏目关键词）、
`ALLOWED_HOST`（主机名白名单 —— 保证只收官网与职能部门，不收学院站）。

两个实用开关：
* `python tools/discover_sources.py seu nju` —— 只重探这几所（需先追加到 `ROSTER`）
* `python tools/discover_sources.py --weak-only` —— 只重探「来源少于 3 个」的学校（补弱项）

**现代框架站**（文章链接是 `/post/detail/xxx`、`?id=123`，路径不带 `.htm` 数字）默认规则一条都
挑不出来。脚本会自动推导一条 `link_re`（把该栏目里最常见的链接形状转成正则），
写进来源配置前会**用抓取器自己的逻辑回放一遍**确认能挑到足够条数。
生成的配置里这类来源标成 `mode=link_re`，页面上表现为稳定可用但稳定性略逊（排在后面）。

探测明细会写到 `_work/discover-report.json`，便于人工复核：
某所学校自动找不到来源时，看报告里「探测 N / 合格 M」，多半是被 `ALLOWED_HOST` 或
`MIN_DATED` 卡掉了 —— 这时要么放宽口径，要么手工写进 `_work/sources-<key>.json`。

### ③ 登记校区：`tools/register_campus.py`

```bash
python tools/register_campus.py --check   # 先看会改哪几处
python tools/register_campus.py           # 真写
```

自动同步 5 处（幂等，可反复跑）：
`refresh.py` 的 `CAMPUS_PREFIX/LABEL/EN`、`template.html` 的 `CAMPUS_NAMES/CAMPUS_ORDER`、
`cloud_update.py` 的 `CAMPUS_NAMES/order`、`.github/workflows/update.yml` 的 `matrix.include`、
`tools/refocus_data.py` 的默认校区列表。

工作流矩阵里每条腿的参数也一并生成：普通校 `--workers 6 --delay 1.2 --timeout 12 --retries 1`，
浙大单独用低速档（`--workers 2 --delay 2.0 --domain-delay 1.0 --rotate`，因为站群 WAF 按 IP 限流），
外链校区（如清华）不进矩阵 —— 本站不抓取，顶栏那项只是跳转链接。**参数理由见 [规模与耗时.md](规模与耗时.md)**。

### 扩到几十所时要注意的三件事

1. **冷启动别一次推平**：首次抓取每个来源要进 8~9 个页面（列表 + 详情），几十所就是上千次请求。
   建议按 8~10 所一批手动触发，批间隔十几分钟，避免各校 WAF 同时盯上你。
2. **超时是最大黑洞**：卡死的来源最坏耗时 = `timeout × (retries+1)`。默认 25×3 = 75 s，
   大规模下单来源卡死几十秒很正常；用 `--timeout 12 --retries 1` 把它压到 24 s。
3. **`index.html` 体积**：条目越多单文件越大（实测 6700 条 ≈ 9.7 MB）。当前四栏只有几百条
   （约 0.4 MB），暂无需担心；条目数若回到数千级别，再回看 [规模与耗时.md](规模与耗时.md)。

### 收录口径：哪些学校不加

**涉国防 / 军事、有保密要求的院校一律不收录** —— 本项目曾按此口径排除国防科技大学
（中央军委直属军校）与「国防七子」中的北京航空航天大学、北京理工大学、哈尔滨工业大学、
西北工业大学；北京大学、中国人民大学亦按用户要求不收。新增校区前请先确认目标不属此类。
