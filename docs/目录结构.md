# 目录结构与「两条链路」的分界

本项目同时抓两类信息源，它们的**稳定性差别很大**，所以在磁盘上也是**完全分开**的：

| 链路 | 抓什么 | 稳定性 | 脚本 | 产物位置 |
|---|---|---|---|---|
| **官网链路**（稳定） | 官网 / 新闻网 / 通知公告 / 职能部门 | **稳定**：20 个源长期 `failed=0` | `fetch_campus.py`（+ `refresh.py --build-only` 建站） | `_work/`（根下） |
| **公众号链路**（不稳定） | 微信公众号历史推文 | **不稳定**：受微信**账号级限流** `ret=200013` 影响，可能整轮拿不到东西 | `fetch_wechat.py` | `_work/wechat/` |

为什么分开：官网源失败是**个别站点**的问题（换地址即可），而公众号失败是**账号维度**的问题
（新登录/久未使用的公众平台账号要等数小时至 1 天）。把文件分开后：

- 清 `_work/` 不会碰到 cookies / 名单 / fakeid 缓存；
- 备份、排查、迁移任一条链路时互不牵连；
- 一眼就能看出"哪堆文件属于哪条链路"。

**两条链路最终都只往同一份 `data/<校区>.json` 里追加**（按 `i` 去重、90 天保留期），
所以**页面是合一的**，只是数据来源分开管理。

## 一、顶层布局

```
university-know/
├── index.html                 ← 成品站点（首屏只内嵌轻量索引，正文按需取）
├── template.html              ← 页面模板（含 __NOTICE_DATA__ 占位符）
│
├── refresh.py                 ← 建站：把 data/*.json 拆成「轻量索引 + 按需分片」（也保留 pkuknow.cn 上游接口能力）
├── fetch_campus.py            ← 官网链路：浙大/上交/西交的官网 + 职能部门
├── fetch_wechat.py            ← 公众号链路：微信公众平台后台接口（wxmp）
├── cloud_update.py            ← 无人值守统一入口（默认只跑官网，--with-wechat 才跑公众号）
│
├── data/                      ← 两链路的**共同**产物：合并后的 JSON（页面数据源）
│   ├── zju.json  sjtu.json  xjtu.json      ← 清华知道为外链，不落数据
│   ├── shard/                 ← 按需加载分片（refresh.py 自动生成，随页面一起部署）
│   │   ├── <校区>.json        ← 该校区全量：切到它时按需加载
│   │   └── <校区>-d.json      ← 详情增量：点开某条通知时才加载（正文/地点/主办）
│   └── *.json.bak             ← 每次覆盖前自动留的上一版（写入保护）
│
├── _work/                     ← 官网链路的中间产物（可整个删掉重建）
│   ├── items-<校区>.json      ← fetch_campus.py 的抓取结果（入库前可检查）
│   ├── registry-<校区>.json   ← 来源注册表（状态/条数/本轮新增/最近检查时间）
│   ├── run.log                ← cloud_update.py 收进来的完整日志（排查用）
│   ├── sources.example.json   ← 补充信息源的模板（参考用，不会被加载）
│   └── wechat/                ← ★ 公众号链路专属目录（见下）
│
├── tests/                     ← 回归测试（全部离线，自带 mock）
│   ├── unit_fetch.py          ← 标题/日期/正文抽取
│   ├── pipeline_test.py       ← refresh.py 写入保护与合并
│   ├── unit_wechat.py         ← 公众号名单/缓存/迁移
│   ├── test_handler.py        ← 云函数 handler 端到端（mock OSS）
│   ├── test_oss_min.py        ← OSS 客户端签名与官方 SDK 对拍
│   └── test_lazy_load.js      ← 页面按需加载/合并（Node 跑，读 index.html + data/shard）
│
├── tools/
│   ├── dev/                   ← 开发辅助脚本（来源侦察/截图/体检）
│   └── oneshot/               ← 已完成使命的一次性脚本（留档）
│
├── docs/                      ← 文档
├── build/reports/             ← 开发期截图与体检报告（纯留档，可删）
├── deploy/serverless/         ← 阿里云函数计算部署包（handler / oss_min / 打包脚本）
├── deploy/edgeone/            ← 腾讯 EdgeOne Pages 发布脚本（免备案渲染）
└── _work/wechat/wechat-名称总表.txt  ← 手工整理的公众号名单原稿（供登记时参考）
```

> **2026-10 整理说明**：原先散在 `build/_check/` 的测试脚本已统一到 `tests/`，
> 开发辅助脚本归到 `tools/dev/`，一次性脚本归到 `tools/oneshot/`，
> 截图/报告归到 `build/reports/`；根目录的 `WX公众号名称列表.txt` 移入 `_work/wechat/`。
> 所有测试脚本的路径引用已按新层级修正，`python tests/xxx.py` 直接可跑。

### `_work/wechat/` —— 公众号链路的全部家当

```
_work/wechat/
├── wxmp-cookie-header.txt     ← ★ 登录后的 Cookie 整行（推荐这种写法，零转录错误）
├── wxmp-cookie-header-<校区>.txt  ← 可选，分校区版本（优先于全局）
├── wxmp-cookies.json          ← 老格式：JSON {"wxuin": "...", "slave_sid": "..."}
├── wxmp-token.txt             ← 可选：手动指定 token（自动取不到时用）
├── wxmp-accounts-<校区>.json   ← 要抓的公众号**完整昵称**名单（外部维护，不改代码）
├── wxmp-accounts.json         ← 全局名单（所有校区共用）
├── wxmp-fakeid.json           ← fakeid 缓存：锁定公众号后不再依赖搜索（可安全删）
├── wechat-<校区>.txt           ← 公开种子链接清单（一行一条，# 开头是注释）
└── wechat-items-<校区>.json    ← 抓取中间产物（--no-import 时的落点）
```

> **旧布局兼容**：早期版本把上面这些文件直接放在 `_work/` 根下。首次运行
> `fetch_wechat.py` 时会**自动迁移**到 `_work/wechat/`（不覆盖新位置已有文件），
> 并且读取时仍会**回退**看一眼旧位置，所以升级不会丢 cookies / 名单 / 缓存。

## 二、哪些文件是"生成物"，哪些是"手工文件"

| 类别 | 文件 | 能不能删 |
|---|---|---|
| **成品** | `index.html` | 删了跑 `python refresh.py --build-only` 重建 |
| **数据** | `data/*.json` | **不能删**（是历史基线）；`*.json.bak` 可删（只是上一版备份） |
| **官网中间产物** | `_work/items-*`、`_work/registry-*`、`_work/run.log` | 可删，跑一次 `fetch_campus.py` 重建 |
| **公众号中间产物** | `_work/wechat/wechat-items-*`、`wxmp-fakeid.json` | 可删（fakeid 会重新搜索） |
| **公众号凭据/名单** | `_work/wechat/wxmp-cookie-header.txt`、`wxmp-accounts-*.json`、`wechat-<校区>.txt` | **不能删**（手工维护；删了要重新登录/重写名单） |
| **官网补充源** | `_work/sources-<校区>.json` | **不能删**（手工维护；本项目当前还没有这个文件） |
| **模板** | `_work/sources.example.json` | 可删（纯参考，不被加载） |
| **测试** | `tests/*.py` | **不能删**（回归基线，改完代码先跑） |
| **留档** | `build/reports/*`、`tools/oneshot/*` | 可删（仅追溯用） |

## 三、两条链路怎么各跑各的

```bash
# 官网链路（稳定，日常就靠它）
python fetch_campus.py                # 浙大/上交/西交
python refresh.py --build-only        # 不联网，用 data/*.json 重建页面
python cloud_update.py                # 抓取 + 重建，一条命令搞定，只输出摘要

# 公众号链路（不稳定，按需跑）
python fetch_wechat.py                # 用 wxmp 按号抓（需 cookies）
python fetch_wechat.py --campus zju   # 只抓一个校区
python cloud_update.py --wechat-only  # 等价：只跑公众号这一步
python cloud_update.py --with-wechat  # 官网 + 公众号一起跑
```

`cloud_update.py` 默认**不跑公众号**（`--with-wechat` 才跑），原因见
[无人值守更新部署.md](无人值守更新部署.md) 第一节：cookies 是凭据、wxmp 有依赖、
云函数无持久盘。**推荐官网走云端、公众号留在本机。**
